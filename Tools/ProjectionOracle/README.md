# Projection materialization oracle

## Child event-property reader

The strict reader accepts child `FromEventProperty` as `{ Event: { Id: string, Generation: uint32, Tombstone?: boolean }, PropertyExpression: string }`, matching Chronicle 19.30.0 (`dfa5ea4`), `Source/Kernel/Contracts/Projections/FromEventPropertyDefinition.cs` and `Source/Kernel/Contracts/Events/EventType.cs`. An omitted `Tombstone` retains the contract's false default. Missing/null required fields, wrong types or casing, and unknown members are rejected; expressions are passed unchanged to the packaged converter. Root event-property operations, nested children/projections, child `All` mappings and `RemovedWithJoin` remain unsupported. `--smoke` and `--check` execute the reader's accepted/rejected-input conformance specs, including converter round-trip assertions.

`value-children-fluent.json` captures public fluent `from(ValueAdded, from => from.addChild<string>(model => model.values, event => event.value))` output: the value-child event registers only `FromEventProperty`, never an ordinary child `From`. Its plain-string array/direct plain-string property shape passes the pinned kernel for every prefix, including repeated values, independent roots and parent removal/recreation. The in-process client test engine admits only that bounded shape; custom identities, nested/context sources, non-string/nullable/formatted values, child removals, overlapping subscriptions, initial state and root mapping/AutoMap overlap for the value event remain rejected. Missing/null seeded values are rejected during replay rather than assigned inferred semantics. Legacy and standard model-bound decorators have no equivalent event-property API, so no decorator support is claimed.

The `count-children-root-first` and `count-children-child-first` fixtures use parent-first lifecycles (the latter filename is historical). Their public standard-decorator declarations produce typed child items. Both are `kernelSemantics`: all 25 captured prefixes agree with actual client engine state and public reads. Ordinary fixture replay uses real validation, without a bypass.

The `add-children-lifecycle`, `add-children-same-property` and `add-children-leading-underscore` fixtures use the public fluent declarations in `when_adding_with_children/given/compiled_projection.ts`. All 39 parent-first prefixes match client engine state and public reads, first through a temporary diagnostic while ordinary validation rejected them, then through ordinary validation after the bounded addition admission. No diagnostic bypass remains. Public fluent, legacy and standard-decorator scenarios exercise the same lifecycle without initial values.

The five `subtract-children-*` fixtures derive independently from public fluent, legacy and standard-decorator compiler output in `when_subtracting_with_children`. The main lifecycle, same-name and leading-underscore fixtures use the fluent declarations; `subtract-children-legacy` and `subtract-children-standard` capture each model-bound compiler path. All 65 prefixes matched engine state and public reads while ordinary validation still rejected subtraction, before extending the shared bounded predicate. The temporary diagnostic was then removed; ordinary replay and exact compiler-input assertions cover all five fixtures.

The six `increment-children-*` and `decrement-children-*` fixtures independently derive from public fluent, legacy and standard-decorator compiler output in `when_stepping_with_children`. Before changing admission, each operation matched engine state and public reads at all 39 prefixes across its own three fixtures. The temporary diagnostic was removed before extending the shared bounded guard. Same-named numeric payloads are deliberately fractional, negative and zero to distinguish unit steps from AutoMap or operand arithmetic. Each operation has ordinary replay, exact compiler-input assertions and public lifecycle coverage in all three styles.

The three `context-child-keys-*` fixtures capture public fluent, legacy and standard-decorator definitions without rewriting their `$eventContext(EventSourceId)` child creation/removal keys. Each style covers 12 parent-first prefixes: repeat child updates, removal and repeated no-op removal, independent source IDs, and parent removal/recreation. Both internal engine state and public reads matched the pinned kernel before admission; ordinary fixture replay and exact compiler-input assertions retain that proof. These fixtures use only the existing metadata/default conversions below. The admitted shape requires one typed plain-string child collection, direct string root mappings, disjoint subscriptions and source-ID parent keys. Other context paths, mixed key strategies, identifier AutoMap collisions, custom parent keys, arithmetic, joins, All mappings, initial state and child-before-parent futures are not admitted.

### Arithmetic-with-children input conversions

These conversions apply only to oracle inputs, never to client output. Equality specs retain and assert emitted metadata/default values, and compare every other wire/header field and every schema body exactly. No reader rule is relaxed.

| Input location | Conversion | Pinned kernel 19.30.0 evidence |
| --- | --- | --- |
| Definition `LastUpdated` | Omit the hash-derived registration timestamp from `wireDefinition`; retain it as fixture `compilerLastUpdated` and in client assertions. No property mapping is removed. | `Source/Kernel/Core/Projections/Engine/ProjectionDefinitionComparer.cs:38,48–53` explicitly ignores registration metadata. `ProjectionFactory.cs:63–79` constructs evaluation and `Pipelines/ProjectionPipeline.cs:121–131` dispatches event steps without reading it; the evaluation source has no `LastUpdated` reader. |
| Root `NoAutoMapProperties` | Supply `[]` only if the compiler omits the property. Preserve any emitted value exactly. | `Source/Kernel/Contracts/Projections/ProjectionDefinition.cs:134` initializes it to `[]`; the oracle already uses that default for children. |
| `eventSchemas[].eventType.Tombstone` | Omit only an exactly `false` flag. Preserve the flag in client assertions and on wire-definition event keys; never discard `true`. | `Source/Kernel/Concepts/Events/EventType.cs:12` defaults the reader's two-argument constructor to `false`. |

The count-, addition-, subtraction- and step-with-children format audits cover root/child definitions, key/value entries, strict contract event/from/removal types, All operations, schema wrappers/headers, read-model and event-schema bodies, event envelopes, contexts and contents. `FixtureDefinition.cs` accepts the remaining definition keys; `OracleRunner.cs` and `FixtureEventContext.cs` accept the remaining envelope/header/context keys. Schema bodies are forwarded intact to `JsonSchema.FromJson`, not filtered by an oracle keyword allowlist. Empty unsupported operations remain empty. The fixtures' ordinary `ReadModelScenario.given` contexts use accepted fields; runtime event types, dates and sequence numbers have the fixture's explicit header/ISO/decimal-string encodings. Optional context fields not emitted by these declarations are not normalized or admitted by this audit.

`constraints-field-key-measurements.json` adds raw-JSON measurements for an unscoped, case-sensitive, single-property text, decimal or float constraint. Each case's `localSteps` prefix has production-client content/hash/key parity; later operations retain exponent-spelling and float-rounding evidence. Text includes quotes, backslashes, measured controls, selected BMP characters, seven supplementary-plane scalars (whose hashes use uppercase surrogate-pair JSON escaping), NFC/NFD distinctions and a failed batch followed by a successful retry. Decimal/float support is an exact finite allowlist, not a general conversion implementation. Regenerate with `--update-events` and verify with `--verify-events`; both use the packaged 19.30.0 kernel, not a live service.

From the repository root, run `yarn install --immutable`, then `yarn oracle:check`. This requires the .NET SDK pinned by the repository-root `global.json` (11.0.100, roll-forward to the latest feature band). Ordinary `yarn test` does not require .NET. To inspect the compatibility boundary alone, run `dotnet run --project Tools/ProjectionOracle -- --smoke`. To intentionally replace committed expectations **after reviewing an engine upgrade or fixture change**, run `dotnet run --project Tools/ProjectionOracle -- --update` and inspect the diff. CI never updates them. The oracle pins `TZ=UTC` and the invariant .NET culture before loading the kernel, so date-time output does not depend on the host. The weekly NuGet probe skips prereleases and executes the fixtures against the latest stable package in a temporary project; drift and incompatible releases are reported without updating the pin or failing the scheduled job.

The oracle pins `Cratis.Chronicle.Testing` **19.30.0** (Chronicle commit `dfa5ea4`) in `ProjectionOracle.csproj`. At check time, it compares each fixture's engine version and commit prefix with the loaded package assembly's informational version; the installed **historical** contracts package version and descriptor SHA-256 are checked against every fixture too. That package is resolved through the root alias `@cratis/chronicle.contracts-oracle` (pinned to 19.31.10), separate from the client's `@cratis/chronicle.contracts`. The package contains Core, Concepts, Contracts, Grpc, Infrastructure, Storage and Storage.InMemory under `lib/net10.0`, but only Testing is exposed under `ref/net10.0`. The project adds aliased compile references to **those same packaged DLLs** using `GeneratePathProperty` and a lockfile, not to a separate kernel checkout. The one internal access is `ProjectionDefinitionBridge`: it reflects the package's transport-to-kernel `ToChronicle` converter and asserts its exact parameter/return signature on every run. This is version-fragile; do not silently fall back to a copied converter. The packaged Core's generated type discovery also requires the matching `Cratis.Arc` runtime assembly. The package embeds Roslyn 5.9 while a transitive dependency exposes a Roslyn 5.0 compile asset, so the project excludes that older compile asset.

The isolated constraint fixtures (`constraints-isolation.json`, `constraints-key-domain.json`, `constraints-property-lifecycle.json`, `constraints-property-covered-removal.json`, `constraints-event-type-siblings.json`, `constraints-event-type-cycles.json`, `constraints-composite.json`, and `constraints-ignore-casing.json`) explicitly select their unscoped client definitions, declare all event schemas and their definition provenance, and assert the effective kernel definitions installed by the packaged testing adapter (ordered event properties, scope, removal and casing). The lifecycle fixtures prove owner-based replacement/removal, fieldless removal events, covered-and-removal validation, and the fact that property claims are never released during whole-batch validation; their accepted history includes hashes for every event. The event-type fixtures install one explicit definition for the complete covered type set (not merged .NET class attributes), include alternative removers and a covered-and-removal event, and capture single and atomic batch cycle releases and rejections. The composite fixture installs multi-property definitions in declared property order (composite events use a `values` object instead of `value`); the oracle passes the order and the fixture's `ignoreCasing` flag through, asserts both on the installed kernel definition, and never joins, folds or compares values itself. They pin the generated `events_constraints.ts` descriptor in addition to the event-sequence descriptor. Each single or batch operation captures the mapped client result, raw contract violations on rejected appends, full accepted content/routes/hashes, and next sequence; rejected operations assert unchanged history and sequence. Only rejected appends are resent to the packaged kernel service to capture its raw response. The original `constraints.json` increment-4 regression fixture keeps its previous runner and meanings. These original isolated fixtures cover unscoped constraints. The separate `oracleGuard` fixture for unsupported key conversions is deferred; the TypeScript specs reject those inputs but do not claim packaged-kernel behavior for them. `constraints-ignore-casing-measurements.json` (`ignoreCasingMeasurements: true`) installs one unscoped, single-property `ignoreCasing` definition over a plain string and, besides the append evidence, records for each key the .NET `ToLowerInvariant` result and its UTF-8 SHA-256, cross-checked against the packaged kernel's own key builder; it measures exactly U+00C9, U+00DF, U+00E9, U+00F8 and U+0301 with no normalization or full Unicode folding. Add new fixture names to `Program.Main`'s required list so `oracle:check` cannot pass without them. `--update-events` rewrites all event fixtures; inspect its diff and retain unrelated fixtures unchanged.

`constraints-case-sensitive-unicode.json` (`caseSensitiveTextMeasurements: true`, mutually exclusive with the other field-measurement modes) installs one isolated, case-sensitive, unscoped, single-property definition over `OracleFieldText.key`, a plain string, without removers. It measures exactly U+039B, U+03BB, U+0416, U+0436 and U+4E2D, individually and in mixed strings with the existing alphabet. It records decoded scalar sequences and kernel UTF-8 key SHA-256, independently cross-checked against direct UTF-8 SHA-256 without casing or normalization. Service appends capture case distinctions, exact-duplicate collisions, raw violation text, stored content/hashes, JSON spelling, canonical distinctions and atomic batch rollback. Both TypeScript decorator modes replay every operation; there are no kernel-only suffixes. Regenerate with `dotnet run --project Tools/ProjectionOracle -- --update-events`, retain only intended fixture changes, then run `yarn oracle:check`. This adds no support for other Unicode scalars or broader key definition shapes.

`constraints-field-types.json` sends literal JSON directly through the packaged single/batch services, without .NET client serialization erasing Guid casing, numeric spelling or date offsets first. Its runner asserts each installed unscoped, single-property, single-event-type definition and records and asserts the effective property schema read through kernel storage. The numeric cases cover both `number/double` and exactly the unformatted `number` property emitted by TypeScript `@field(Number)` and `ConceptAs<number>`. The packaged testing adapter's registration methods are no-ops, so the runner replaces the number case's input schema in its scenario-local discovered-schema catalog before appending. That additional reflected catalog access asserts its exact packaged shape and fails closed on drift; kernel conversion and constraint evaluation remain unchanged. Supported cases prove dashed Guid comparison and lowercase violation details, safe-integer boundaries, `1` versus `1.0`, same-source replacement, batch rejection, unchanged history and next sequence, and stored hashes. Separate `oracleGuard` cases capture fractional/exponential and unsafe-integer formatting, raw negative zero (which TypeScript's production serializer emits as `0`), and `DateTime` keys with the installed `string/date-time` schema that TypeScript emits for `Date`: equivalent instants with different offsets collide, and fractional seconds disappear from keys/details. This is not `DateTimeOffset` / `date-time-offset` evidence. Those guards do not authorize general numeric or date-key support. Raw history reads expose kernel-normalized content, not the .NET client's typed deserialization. TypeScript scenarios preserve client-serialized payloads; their deterministic hashes outside the proven domain are scenario-local, and observed Hash projections reject such schemas.

`constraints-scopes.json` adds isolated cases for all seven nonempty combinations of source-type, stream-type and stream-ID scopes: case-sensitive single-string property keys, singleton event-type constraints and two-type/two-remover cycles. It captures exact/default/empty routes, selected versus unselected dimensions, case-sensitive routing, scope-local replacement/removal, batch rollback and both TypeScript batch overloads. Each case installs its definition alone. Delimiter aliases are `oracleGuard` cases: property scopes flatten unescaped strings while event-type scopes compare tuples; TypeScript scenarios continue rejecting those route characters.

`constraints-event-sequences.json` installs one unscoped property, two-type cycle or singleton event-type definition per case, each declaring the event sequences it applies to (`event-log`, `outbox` with `event-log`, or `outbox` alone). The runner sets the packaged client definition's `EventSequences` and asserts them on the installed kernel definition. The packaged scenario appends to the event log, so the cases capture full enforcement where the event log is included and no validation, claiming or release where it is not.

The scope adapter is the fixed **packaged** testing adapter in 19.30.0, not a replacement validator. `scope-wire.mjs` uses the pinned TypeScript contract encoders from the `@cratis/chronicle.contracts-oracle` alias for scope definitions and every append request. The oracle decodes those protobuf bytes before constructing the client scope, asserts selected `*` versus omitted/null scope members, and checks the effective installed kernel definition (including scope). It runs every scoped operation twice in independent packaged scenarios: once through the .NET client and once through the decoded TypeScript request. Success, sequences, errors, complete content/routes/hashes and next sequence must agree. Raw violations come from the wire scenario. In particular, an empty TypeScript string is omitted on the wire; assigning `""` to a nullable .NET contract member is not used as evidence of that omission. Routing precedence is prepared explicitly in the wire encoder and checked against production TypeScript preparation by the scenario specs; the oracle does not implement constraint evaluation.

The fixtures are checked against the generated `@cratis/chronicle.contracts` 19.31.10 wire layout, including key/value **arrays** for event-type dictionaries. Their definitions were hand-written against the contract version recorded in each fixture's `definitionSource` (19.6.1 for the original projection fixtures) before the shared `ProjectionDefinitionCompiler` landed, then converted by the packaged Grpc converter and executed by the packaged engine; see `definitionSource` in each fixture. The descriptor SHA-256 of the installed generated `projections.ts` file detects TS contract drift. Each fixture records its format version, a `kind` (`kernelSemantics` for kernel behavior a TypeScript evaluator must reproduce, or `oracleGuard` for kernel behavior outside the phase-1 evaluator boundary or the oracle's own fail-closed boundaries; the evaluator asserts rejection rather than comparing snapshots), engine version/commit, contract version/hash, read-model and participating event schemas, explicit ordered event contexts (lossless string sequence numbers), wire definition and per-event expectations. Unknown event/context and wire fields fail closed. Root `Join` entries and `All` mappings are read as strict packaged contract definitions; `SubscribesToAllEvents` is passed to the packaged converter and factory, not simulated by the runner. Children are read one level deep with `From`, `Join` and `RemovedWith` only; any other child operation fails closed. Child join event types must have declared schemas just like root join event types. Contexts can supply `eventSourceType`, `eventStreamType`, `eventStreamId`, `correlationId` (GUID), `causation` (`occurred`, `type`, string `properties`), `causedBy` (`subject`, `name`, `userName`, recursive `onBehalfOf`), `tags`, `hash` and `subject`; omitted values use the kernel defaults. Events within one fixture must share an event store and namespace; omitted values use the kernel's `NotSet` sentinels. For a failing final step, put `expectedError: { "type": "...", "message": "..." }` on the event; the corresponding expected snapshot includes `error` beside `engineState` and `publicRead`. An unexpected exception fails the run rather than producing an expected error.

The runner creates a real `ProjectionFactory` projection and calls the public `ProjectionPipeline.Handle` with the complete production step sequence: `ResolveKey → SetInitialState → DecryptInitialState → HandleEvent → EncryptChangeset → StoreFutures → ResolveFutures → SaveChanges`. Events are appended to the in-memory sequence before handling. Strict proxies guard the factory lookups, compliance and replay-cache dependencies, and unsupported futures operations. The one permitted futures call is `GetFutures()`: the production tracker probes durable storage once on its first event, so the empty in-memory store returns no futures. Plain schemas do not call compliance. It skips unrelated events as the production subscription filter does. Snapshots contain the sink's **engine state**, including `__initialized` and explicit nulls, alongside the schema-normalized **public read** produced by the same `ExpandoObjectConverter.ToJsonObject` used by `ReadModels.GetInstanceById`. Keys absent from `publicRead` mean no materialized instance; missing fields and explicit null fields remain distinguishable in `engineState`. The separate `ProjectionReadModelProcessor` replay loop in Chronicle.Testing is never called.

For root joins, the production factory wires `ResolveJoin` to each `From` clause that maps the joined property, including inferred AutoMap. It reads the latest prior source event from the packaged event-sequence store. Later join-only events create `Joined` changes against empty state; the packaged sink applies these to every matching existing root. No joined read-model row, custom join-state store or durable future is involved. The TypeScript evaluator keeps a replay-local latest-event lookup, not accumulated joined properties. The relevant pinned sources are [ProjectionFactory](https://github.com/Cratis/Chronicle/blob/v19.30.0/Source/Kernel/Core/Projections/Engine/ProjectionFactory.cs), [ResolveJoin](https://github.com/Cratis/Chronicle/blob/v19.30.0/Source/Kernel/Core/Projections/Engine/ProjectionEventContextExtensions.cs), [SetInitialState](https://github.com/Cratis/Chronicle/blob/v19.30.0/Source/Kernel/Core/Projections/Engine/Pipelines/Steps/SetInitialState.cs) and [InMemorySink](https://github.com/Cratis/Chronicle/blob/v19.30.0/Source/Kernel/Storage.InMemory/Sinks/InMemorySink.cs).

This is a **materialization proof**, not a live-kernel storage oracle: no Orleans scheduling, protected-field compliance/decryption, stored futures, nested children, general child-join placement/backfill, MongoDB BSON conversion or Docker-backed keyed read is exercised. In particular, the in-memory sink writes its own `id` property, whereas a persistent sink can use `_id`. Arithmetic support remains limited to root source-ID projections with number/double or int32 accumulators and direct numeric event-property operands. Uint32 targets, nonnumeric/nullable schemas, text assignments into accumulators, clearing, other numeric formats, dynamic/context operands, custom/constant keys, arithmetic with joins, arithmetic with children outside the bounded count and unformatted addition/subtraction/step shapes above, and arithmetic combined with `fromEvery` or `fromAll` remain rejected. The TypeScript evaluator admits only the bounded root SequenceNumber-to-string All mapping alongside ordinary string mappings, for both `fromEvery` (handled types only) and `fromAll` (all types, with default All settings). Other All shapes, including empty all-event subscriptions, remain rejected before replay; their `oracleGuard` fixtures prove packaged-kernel behavior, not evaluator support. All other children restrictions remain unchanged. Joins are limited to one root join event type, source-ID keys, a direct non-identifier join target populated by a `From` clause, plain string read-model properties and direct plain string event-property assignments. Multiple joins, empty effective mappings, join-only projections, initial state, other schemas/expressions, overlapping `From`/`Join` events or destinations, mutating the join target, child joins, `removedWithJoin` and joins combined with children or arithmetic reject before replay. Live-kernel differential coverage for storage-sensitive cases belongs to later increments. Keep the package pin and expectations together when upgrading.
